## 2. Root cause (decisive finding)

MuseTalk download_weights.sh silent fail:
- script prints 'All weights have been downloaded successfully!' and returns 0
- but find /root/MuseTalk/models -maxdepth 2 -type f is empty - no files downloaded
- only 7 empty dirs created: dwpose, face-parse-bisent, musetalk, musetalkV15, sd-vae, syncnet, whisper

Why silent fail (hypotheses):
1. HF token env var name mismatch (HF_TOKEN vs HUGGING_FACE_HUB_TOKEN)
2. Modal debian_slim image missing git-lfs apt package
3. download script uses || true to swallow sub-command errors then echoes success
4. stdout tail 1500 chars dominated by pip install satisfied messages, real download attempt log not visible

Violation: Phase 2 scaffold app_musetalk.py copied MuseTalk README example bash download_weights.sh without verifying script works in Modal env (no GUI, no git-lfs, no HF interactive login).

Gate 1 should-do (next time mandatory): Third-party download/install scripts must be tested in Modal sandbox + verify real artifacts land on disk, before integrating into production cold start.

Lesson entry (lesson_template format):

- root cause: download_weights.sh assumes cwd / git-lfs installed / HF login present. Modal env satisfies none.
- prevention: Integrate third-party install scripts only after subprocess.run in small PoC container + verify real artifact lands
