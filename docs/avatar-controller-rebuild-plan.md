## 為什麼要做（問題陳述）

蘇菲的「畫面框」(`<video id=liveVideo>`) 只有一個、但今天有**至少 6 段程式各自去動它**：

1. `AvatarDirector` — 有 `_seq` 排隊機制（半套管家）
2. `animation-pool` idle rotator — 待機輪播
3. `animation-pool` pre-call rotator — 未通話前豐富輪播
4. cold-start watchdog — 冷開機自癒重試
5. `playPreRollGreeting` — 開場招呼（直接設 src）
6. speaking 層 / lipsync 切片 — 講話視覺

**它們互不知道對方在做什麼**。冷開機 / 慢網路時撞在一起 → `play() interrupted` → 卡死 / 黑屏 / 招呼被蓋。

**今天踩的 6 個 bug 全是這個根**：冷開機空白 → 聲音斷 → 招呼沒了 → 自動播放擋 → 快取鎖舊版 → 載不完。每個單獨修都對、合起來互相打架。

**歷史**：這塊從 v1.9.1 補到 v2.0.33、約 **15+ 次補丁**、從沒打掉重做。這是「補 OK 繃補到爛」、不是「沒人修」。

---

## 重整要改什麼（核心）

**一句話：把「6 個遙控器搶一台電視」改成「1 個管家、誰要轉台都跟管家排隊」。**

### 新架構
- **單一控制器** `AvatarStage`（唯一能碰 `video.src` / `.play()` 的程式）
- 對外只開幾個門：`showIdle()` / `showGreeting()` / `showSpeaking()` / `showLipsync(phrase)` / `freeze()`
- 內部：一個**指令佇列 + 當前擁有者編號**。每個請求拿號碼牌、只有最新號碼牌能動畫面、舊的自動作廢 → **不可能再互相打斷**
- 狀態：載入中(顯示靜態臉) → 待機 → 招呼 → 講話 → 嘴對齊 → 回待機。轉場清楚、單向

### 上面那 6 段全部改成「跟管家下單」
- rotator / watchdog / preroll / speaking / lipsync 都**不再直接碰 video**、改呼叫 `AvatarStage.showXxx()`
- 管家內建手機輕量模式（已有 `IS_MOBILE` 偵測可沿用）
