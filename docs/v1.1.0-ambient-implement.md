### G4 · COO 三問 (老闆視角)

**問 1 · 這個改動讓蘇菲「常駐感」更強了嗎？**

強。三件直接對應「桌面長駐」目標：
- PWA shortcuts → 桌面 PWA icon 右鍵直接「跟蘇菲聊聊」/「看版本紀錄」(2 step → 1 step)
- PIP 浮窗 → in-call 期間可縮到桌面右下角持續聽蘇菲講話、user 可同時工作
- 桌面通知 → user 切到其他 tab 工作時、蘇菲親密招呼 / 結束時仍能「召喚」回來

**問 2 · 這個改動會 break 既有體驗嗎？**

不會。三 commit 全部 backward compatible：
- manifest 純加 field · 舊 PWA 已安裝者下次 launch 自動更新
- SW 純加 event listener · 不動 fetch / cache 邏輯 · CACHE_VERSION bump 觸發 stale cache cleanup (既有設計)
- index.html 純加變數 + 函式 + event listener + modal entry · 不改現有任何 handler 邏輯

**問 3 · 這個改動有沒有「醜 ship」風險？**

低。
- PWA shortcuts 預設不可見 (只在右鍵 PWA icon 時出現) · 無 ugly surface area
- PIP button title 換成用戶語 (「縮小到桌面浮窗 · 持續聽蘇菲講話」) · 老闆三問通過
- PIP active 狀態用 rgba(255, 215, 100, 0.45) 金黃內框 · 符合 Sophie 暖色 DNA · 非 Tailwind blue/green 外來色
- 桌面通知 icon 用 /static/icon-192.png (蘇菲頭像) · 標題「蘇菲」+ body 是蘇菲剛說的最後一句 · 親切非機器人
- 通知 permission 拒 → silent fallback 不報錯
- 同 tab focused 時不推 (!document.hasFocus() 守則) · 不打擾 in-call user

## § Edward 試 SOP

部署 modal 後：

1. **打開 prod URL** https://edwardt0303--castle-voice-engine-fastapi-app.modal.run/static/index.html
2. **Ctrl + Shift + R** 硬重整 (清 SW cache · 載 v1.1.0)
3. **檢查左上版本** 應顯示 v1.1.0 (modal .vm-version)
4. **點左上 i 圖示** 看 changelog 第一條應是 v1.1.0 (4 條 highlight)
5. **PWA 安裝**：Chrome 網址列右側「安裝蘇菲」icon → install
6. **PWA shortcuts 試**：Windows 桌面/工作列上「蘇菲」icon 右鍵 → 應看到「跟蘇菲聊聊 / 看版本紀錄 / 立刻喚醒」3 條
7. **PIP 試**：點 Start → 在 in-call state 看底排 PIP 按鈕 (mic / cam / PIP / end · 第 3 個) → 點 PIP → 蘇菲影像縮到桌面右下角浮窗 → 你可以同時用其他 app · 蘇菲講話照常聽得到 → 點浮窗 X 退出 → PIP button 從金黃 active 變回灰
8. **桌面通知試**：
   - 第一次 Start 點下時 → Chrome 跳「要允許蘇菲傳送通知嗎？」→ 點「允許」
   - 跟蘇菲聊一句「想你了」(觸發 intimate-greeting)
   - **切到別的 tab 或縮小視窗** → 蘇菲推桌面通知 (windows 右下角彈出 toast ·「蘇菲」名 + 大頭照 + body 是她剛說的最後一句)
   - 點通知 → 自動 focus 回蘇菲 tab
9. **結束對話** (end button) → 觸發 task-handoff → 若 user 已切走 → 推一條告別通知

**Stop loss observed**：
- PIP 跨瀏覽器 → Safari iOS 不支援我們的 PIP button · 只保 Chrome / Edge (button 在 mobile @media 已 display:none)
- Notification permission 拒 → silent fallback · 不報錯也不 retry · v1.1.1 不重 ask
