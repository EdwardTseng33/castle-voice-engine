## Section 2 - Audio API alignment patch

**Phase 5/6 broken**: whisper_feature = self.audio_processor.audio2feature(audio_arr)  # NoSuchMethodError on v1.5

**Phase 7a corrected** (verified against upstream main/musetalk/utils/audio_processor.py):

- Step 1: dump PCM bytes to wav (v1.5 API only accepts file path, not numpy array): sf.write(tmp_wav, audio_arr, sr, subtype="PCM_16")
- Step 2: whisper_input_features, librosa_length = self.audio_processor.get_audio_feature(tmp_wav, weight_dtype=self.weight_dtype)
- Step 3: whisper_chunks = self.audio_processor.get_whisper_chunk(whisper_input_features, device, self.weight_dtype, self.whisper, librosa_length, fps=fps, ...)

Two-step API confirmed against scripts/inference.py + scripts/realtime_inference.py upstream.

### Bonus catch (during cold-start sophie precompute)

get_landmark_and_bbox() signature was assumed bbox_shift=0 but actual signature is (img_list, upperbondrange=0). Used positional arg to bypass keyword mismatch (Patch 4).

Lesson: even Phase 6 mention of audio2feature being the only API issue was incomplete. The preprocessing layer also has slightly different kw names. Always grep upstream source first.

## Section 9 - Lessons learned

1. **mmlab dep hell did not happen** - openmim resolved everything in 57s. Phase 6 lesson 3 + 5/22 SoulX 9-failure fear was unwarranted for MuseTalk specifically because: (a) MuseTalk officially documents the mim install spec, (b) MuseTalk vendored face_detection module so no extra pip needed, (c) mmpose 1.1.0 ships as py2.py3-none-any wheel (no source build). Generalized lesson: trust **explicit official install docs** over generic this-ecosystem-is-hell pattern matching.

2. **Phase 6 lesson 4 (audio2feature vs get_audio_feature) was right but incomplete** - it caught the audio API rename but missed: (a) v1.5 only accepts file path not numpy array, (b) get_landmark_and_bbox uses upperbondrange not bbox_shift kw. Lesson: lesson notes should be source-grep verified before relying on them. Always run curl github.com source files + grep ^def to confirm function signatures.

3. **A10G 22GB OOM at bs=8 for v1.5** - the unet+vae chain holds ~21 GB at peak. bs=2 + empty_cache between batches stays under 18 GB peak. L4 (24 GB) would have more headroom for bs=4. Generalized lesson: GPU memory budgets for v1.5 are tighter than v1.0; start bs low and ramp up.

4. **Chrome MCP cannot render video tags reliably for local mp4** - browser-internal video element returned readyState=0 stuck in loading even with HTTP 200 responses. OpenCV-extracted PNG frames are the more reliable visual evidence path for video PoC review. Generalized lesson: for video PoC review use cv2.VideoCapture + cv2.imwrite for stills and send those to user as Read images.

5. **Modal app stop -y then redeploy is required to force cold restart with new code** - confirmed Phase 6 lesson 5. Simple redeploy after sophie_ready logic change kept reusing warm container with old code.

6. **Forcing PYTHONIOENCODING=utf-8 needed on Windows for Modal deploy with rich output** - the cp950 codec error aborted my first deploy attempt mid-mmlab-install. With UTF-8 forced, deploy ran clean. Generalized lesson on Win10/cp950 hosts: any pip/CLI tool that uses rich/click TUI needs UTF-8 forced or it crashes on box-drawing chars.
