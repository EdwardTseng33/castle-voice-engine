## 目標

把 Phase 1 的 HTTP multipart stream（高延遲 · 不適合雙向）換成 WebRTC SFU 路徑：

- Edward mic → LiveKit room → backend ASR worker
- musetalk-poc renderer worker join room as `sophie-renderer` → push idle/speaking video track
- Frontend (Phase 3) subscribe video track via LiveKit Web SDK

## Edward 手動步驟（3 步 · 我不能代做）

### Step 1 · 註冊 LiveKit Cloud Build（免費 100 GB/月）

> 為什麼我不代註冊：建新帳號 = `prohibited_actions` · 必須你親自做。

1. 開 https://cloud.livekit.io
2. 點 **Sign up** · 用 `edwardt0303@gmail.com`（或 castle-voice-engine 開發 email）
3. 確認 email · 進 dashboard
4. 點 **Settings → Keys** · 建一組 API Key
5. 記下：
   - `LIVEKIT_API_KEY`（格式：`APIxxxxxxxxxxx`）
   - `LIVEKIT_API_SECRET`（格式：~ 32 char random）
   - `LIVEKIT_URL`（格式：`wss://your-project.livekit.cloud`）

**不要把 secret 貼進對話**。下一步直接灌進 Modal secret。

### Step 2 · 建 Modal secret

在 Edward 端終端（不在 Claude 對話）：

```bash

python -m modal secret create livekit-creds \
  LIVEKIT_API_KEY=APIxxxxxxxxxxx \
  LIVEKIT_API_SECRET=secretxxxxxxxxxxxxxxxxxx \
  LIVEKIT_URL=wss://your-project.livekit.cloud
```

驗證：

```bash
python -m modal secret list | grep livekit-creds
```

### Step 3 · Deploy 兩個 Modal app


## Verify 腳本（Edward 跑完 3 步後自審）

### A · check creds + SDK installed

```bash
curl https://<your-castle-voice-engine-url>/livekit/health
```

Expect:
```json
{
  "ok": true,
  "livekit_creds_set": true,
  "livekit_url_set": true,
  "livekit_sdk_installed": true,
  "modal_sdk_installed": true,
  "phase": "v0.10 Phase 2"
}
```

任何 `false` → 找對應 step fix。

### B · mint token

```bash
# 帶 cookie · 從瀏覽器 dev tools copy
curl -X POST https://<your-castle-voice-engine-url>/livekit/token \
  -H "Cookie: sophie_auth=<your-signed-cookie>" \
  -H "Content-Type: application/json" \
  -d '{}'
```

Expect:
```json
{
  "ok": true,
  "room": "sophie-abc12345-1716624000",
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "url": "wss://your-project.livekit.cloud",
  "identity": "edward-1716624000",
  "expires_in_s": 300
}
```

### C · LiveKit Web Playground 真實驗

> **這是 Phase 2 的 ship gate** · screenshot + frame count 是真實 evidence

1. 開 https://meet.livekit.io
2. 點 **Connect**
3. 貼上 `url`（從 step B response）
4. 貼上 `token`（從 step B response）
5. 加入房間 - 此時你會看到自己（mic + cam）
6. 觸發 sophie-renderer：

```bash
curl -X POST https://<your-castle-voice-engine-url>/livekit/spawn \
  -H "Cookie: sophie_auth=<your-signed-cookie>" \
  -H "Content-Type: application/json" \
  -d '{"room":"sophie-abc12345-1716624000","mode":"idle"}'
```

Expect:
```json
{
  "ok": true,
  "status": "spawned",
  "room": "sophie-abc12345-1716624000",
  "mode": "idle",
  "modal_call_id": "fc-xxxxxxxxxxxxxxxxxx"
}
```

7. 等 5-10 秒（Modal cold start + LiveKit handshake）
8. 在 LiveKit playground 看見 `sophie-renderer` participant 加入 + 推 video track
9. 觀察：
   - idle 影片連續播（不閃 / 不卡）
   - 延遲 < 3 秒
   - 4 個 idle 變體輪播（每 8 秒切一個）

### D · Modal log audit

```bash
python -m modal app logs castle-voice-engine-musetalk-livekit-publisher --follow
```

Expect lines:
```
[publisher] connected to room=sophie-... url=wss://...
[publisher] track published · sid=...
[publisher] DONE · room=... frames=N dt=...s reason=duration_reached
```

`frames=N` 應該 `~= duration_s * fps`（e.g. 30s × 25fps ≈ 750 frame）。

## 退場路徑

| 失敗點 | 退場 |
|---|---|
| LiveKit Cloud 註冊不下來 / 月費異常 | 退 self-hosted Mediasoup（0 月費 · 但配置更複雜 · v0.11 backlog）|
| `pip install livekit==0.20` 在 Modal slim 失敗 | 換 livekit Python SDK 對應版（檢查 PyPI latest stable）|
| backend frame → LiveKit track 串不通 | 退 HTTP streaming + 前端 MediaSource buffer（Phase 1 already work）|
| 串通但延遲 > 3 秒 | 檢查 Modal cold start + 加 `keep_warm=1` + `container_idle_timeout` |
| LiveKit SDK API name 不對（VideoSource / VideoFrame / VideoBufferType）| 看 `python -c "from livekit import rtc; print(dir(rtc))"` 對照真實 SDK + 改 publisher.py 對應段 |

## 退場判定（可行 / 不可行）

**可行**（給蘇菲整合 + 派 Phase 3）：
- A / B / C / D verify 段 4 個都 PASS
- frames=N ≈ duration_s × fps
- 延遲 < 3 秒（暖機後）

**不可行**（退 HTTP streaming 或換 Mediasoup）：
- C 段 playground 看不到 sophie-renderer participant
- D 段 modal log 顯示 livekit SDK ImportError 或 publish_track exception
- frames=0 或 < 10% 預期值
