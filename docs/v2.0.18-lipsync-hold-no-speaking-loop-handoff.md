# v2.0.18 Lipsync Hold / No Speaking Loop Handoff

Date: 2026-05-25
Owner: Howl / Codex

## Verdict

Edward was right: the previous visible mouth movement was not true lipsync. It was the `sophie-speaking.mp4` speaking loop being shown over the idle video.

For this patch, the speaking loop is disabled by default. Audio start now keeps the idle 1-4 base visible while waiting for a real lipsync hit. When a lipsync mp4 plays, it remains the visual owner until the audio output is done.

## Changed Files

- `castle/static/index.html`
- `castle/static/animation-pool.js`

## Behavior Changes

- Default: `sophie-speaking.mp4` no longer turns on during voice output.
- Opt-in rollback: add `?speaking_loop=1` if the old speaking-loop fallback is needed for comparison.
- True lipsync visual source is tracked as `window.__sophieVisualSource = "lipsync-mp4"`.
- If a lipsync clip ends while Sophie is still speaking, the same lipsync clip is replayed until audio output ends, capped at 30 seconds.
- After lipsync ends, the avatar returns to idle, not speaking loop.

## Acceptance Standard

Pass only if the active visible video source becomes `/lipsync/phrase_xxx.mp4`.

Fail if the visible movement comes from `/static/sophie-speaking.mp4`.

Test URL:

`/static/index.html?lipsync=1&lipsync_test=phrase_074&lipsync_repeat=1`

Expected console state during playback:

- `window.__sophieVisualSource === "lipsync-mp4"`
- `window.__sophieAvatarDirector.getState().mode === "lipsync"`
- `document.getElementById("liveVideo").currentSrc` contains `/lipsync/phrase_074.mp4`
- `document.getElementById("liveVideoSpeaking").classList.contains("is-visible") === false`

## Remaining Product Gap

This is still not full realtime generated lipsync for arbitrary 10-second replies. It only prevents fake speaking-loop fallback and holds the real lipsync visual when a phrase mp4 is available.

To cover every spoken word naturally, the next structural step is to generate lipsync from the actual response audio, either:

- chunked MuseTalk/LatentSync mp4 generation, then append/play chunks, or
- LiveKit/WebRTC compositor with a generated mouth stream over the idle base.

## v2.0.19 Addendum

Date: 2026-05-25

Edward reported that normal dialogue still looked like idle with no moving mouth. Root cause: most arbitrary replies do not match the 100 pre-rendered phrase list, so after disabling `sophie-speaking.mp4` there was no mouth-motion source left.

- Fallback source is `/lipsync/phrase_001.mp4` by default, not `/static/sophie-speaking.mp4`.
- Query override: `?lipsync_fallback_id=phrase_021`.
- Query disable: `?lipsync_fallback=0`.
- Test mode: `?lipsync_fallback_test=1` simulates 10 seconds of speech and holds the fallback lipsync clip.
- Ready log is now `Voice Path v2.0.19 ready - real lipsync fallback, speaking loop disabled - 2026-05-25`.

Important honesty note: this makes the mouth visibly move through arbitrary speech using a real lipsync clip, but it is still not word-accurate realtime lipsync. Word-accurate lipsync requires generating a new mouth track from the actual response audio.
