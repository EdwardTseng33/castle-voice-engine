### Audit 2 · Modal A10G 月費 + Cost Ceiling

**事實**（從 Modal pricing page 2026-05 抓）：
- Modal **A10**（非 A10G、可能 SKU 對齊）= **$0.000306/sec ≈ $1.10/hr** ✅ 對齊 ARCHITECTURE_FIX_PLAN 估計
- H100 = $0.001097/sec ≈ $3.95/hr（ARCHITECTURE_FIX_PLAN 寫 $5.50/hr 是樂觀）
- L4 = $0.000222/sec ≈ $0.80/hr（A10 之外的 budget 候選）
- CPU = $0.0000131/core/sec
- Memory = $0.00000222/GiB/sec
- Starter 方案：**$30/月免費額度**（含在月費中）
- Modal 字面：「never pay for idle resources — just actual compute time」= cold start 期間不計費（但仍實占 SLA 5-8 秒）

**ARCHITECTURE_FIX_PLAN 估算 verify**：
- 60 hr × $1.10 = $66/月 = ✅ 對齊
- 待機 CPU < $1 = ✅ 對齊（A 待機 = Modal scale to zero · GPU $0）
- 顯卡冷啟動 overhead = ✅ 字面不計費（但 SLA 5-8 秒實占）

**真實 cost 隱憂 / 漏洞**：

| # | 隱憂 | 評估 |
|---|---|---|
| 1 | MuseTalk model 載入 ~5-10 GB · 第一次 cold start 可能 30-60s（含 model download + warmup） | 字面不計費但占住啟動 SLA · 「叫蘇菲 → 開講」延遲體感重 |
| 2 | Phase 3 鏡頭 MediaPipe ~150MB · 跟 MuseTalk 同 container 載入 = 累加 cold start | 對 daily driver OK · 對「會議模式秒接 join」UX 破口 |
| 3 | Modal **container lifetime / keep-warm** 條款 pricing page 沒揭露 · 必 verify | 若 keep-warm 5 分鐘 = 每次 Edward 想 wake 都吃 cold start |
| 4 | 對外 3 角色擴展 cost 真實估： | |
|   | - **訪談**（30-90 min × 估算每月 10 場）= 5-15 hr/月 ≈ $5.5-16.5 | 小、OK |
|   | - **會議**（60 min × 估算每月 20 場）= 20 hr/月 ≈ $22 | 中等、OK |
|   | - **代理人**（8 hr/day × 22 工作日）= 176 hr/月 ≈ $194 | 大、Track B ship 前要 budget evaluation |
| 5 | 60 hr/月 個人用量 + 代理人 176 hr/月 + 訪談 + 會議 = 可能 250-300 hr/月 ≈ $275-330/月 | Modal Starter $30 額度遠不足、需升 Team 或加付（cost ceiling alerting 必開）|
| 6 | Modal pricing page **沒有明寫 budget alerting / spending cap feature** | 完整 audit 必跑 Modal dashboard verify「Set budget」/「Spend alerts」是否存在 |
| 7 | 同 SKU 別誤判：**A10** 是 SXM 還是 PCIe？A10G = AWS NVIDIA A10G（不同於原 A10）· MuseTalk requirements 必 verify 配對 | 卡西法 Phase 1 deploy 時應該已驗、但 v0.7 部 MuseTalk 換 image 必複測 |

**Verdict 2**：
- Track A（Edward 自用 60 hr/月 $66）= **GO** with conditions：
  - 必 Edward verify Modal dashboard 是否有 spending cap / budget alert（Modal pricing 字面沒寫）
  - 必 verify Modal A10 SKU 是 A10G 還是其他 A10 變體（MuseTalk image 對齊）
  - 必設 $100/月 hard ceiling（超過自動 stop · Modal 沒原生 = 蘇菲手寫 cron 每天看 spend）
- Track B（對外 3 角色擴展到 250-300 hr/月 $275-330）= **CONDITIONAL GO**：
  - 升級 Team 方案 $100 額度
  - 升 Tier D Edward 親口拍板月費門檻（沙利曼授權矩陣鐵律：> $50/月 Tier D）
  - 代理人模式必設 hard cap（24 hr/day 之內、不可意外跑滿）
  - 對外場景 cold start 5-8 秒 + 50-60s model warmup 對「會議秒接」UX 破口、必先 Phase 3.5 keep-warm 策略（Modal warm pool / pre-load）

### Audit 3 · Breeze BREEZE_AUTH_TOKEN Stewardship

**事實**：
- Phase 1 PoC 已 deploy `castle-voice-engine-breeze-poc` Modal app · 認證 token = `BREEZE_AUTH_TOKEN`

**v0.7 ship 前必跑**：

| 檢查 | 方法 |
|---|---|
| token 是否在 git repo？ | `git log --all -p \| grep BREEZE_AUTH_TOKEN`（蘇菲跑、不要在 conversation echo result）|
| token 是否在 .md / handoff / spec / log？ | `grep -rE "BREEZE_AUTH_TOKEN\s*=\s*[A-Za-z0-9_-]+" .`（命中 = redact + rotate）|
| Modal secret 配置？ | `modal secret list` Edward 跑、確認有 `breeze-auth-token` entry、不應在程式 hardcode |
| token rotation 政策？ | **未立** = NO-GO（必補：每 90 天 rotate · sulima 設 cron 提醒 · Edward 一個人 know）|
| Edward + Anthropic + Modal 三方誰可見？ | Edward only · token revoke 流程必文件化 |
| 5/22 OpenAI key leak 同類 risk？ | secret-scan.sh v5.4.20 已含 OpenAI / Anthropic / Slack / GitHub / AWS / Stripe pattern · 必加 BREEZE_AUTH_TOKEN（可能是 random `Bearer xyz...`、grep 通用 token pattern 應 catch）|

**對外 3 角色擴展風險**：
- 訪談 / 會議 / 代理人都會大量 ASR call · token 用量上去 = MediaTek（聯發科）的 Breeze API quota policy 必 verify（Breeze 是聯發科免費還是有 quota？BREEZE_AUTH_TOKEN 怎麼 issue 的？）
- 代理人 8hr/day 跑 ASR = 一天可能 100+ requests · MediaTek 帳號限制是什麼？

**Verdict 3**：
- Track A 自用 = **GO** with conditions：
  - Modal secret 配置 verify（Edward 跑 `modal secret list`）
  - token 不在 git / .md / log（蘇菲跑 secret-scan + grep）
  - 90 天 rotation 政策立 SOP（沙利曼立 sulima.md 新段）
  - secret-scan.sh 加 Breeze pattern（若 fixed prefix · 否則靠通用 token regex 兜底）
- Track B 對外 = **CONDITIONAL GO**：
  - Breeze API quota / rate limit / 商業化使用條款 verify（**未做**、Phase 1 PoC 沒揭露 MediaTek 的 ToS · 對外 ship 前必 verify）
  - 若 MediaTek Breeze API 是「研究用」、對外商業化 = block；換為 Whisper（OpenAI MIT、本機跑或 Modal 跑）或 Distil-Whisper（更輕）
