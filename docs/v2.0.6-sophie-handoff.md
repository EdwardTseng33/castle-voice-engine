## Current State

The live app is on `v2.0.6`.

The current stable mode intentionally keeps the avatar on a single long-running video source by default. This avoids the severe flicker caused by repeatedly switching between idle, speaking, action, and lipsync MP4 files.

Lipsync is not enabled in the default stable URL. It is opt-in through URL flags.

## Current Known Issues

### 1. Stable mode has no lipsync by design

Default stable URL has `window.__sophieEnableLipsync = false`.

This is intentional. It prevents flicker until a no-flicker compositor path exists.

### 2. User may think Sophie is not responding if not logged in

Unauthenticated `/auth/whoami` returns `401`.

If the user says "I talk but Sophie does not respond", first verify:

- Google auth is complete
- Start button was pressed
- microphone permission is granted
- browser is in active call state
- Realtime data channel received `session.updated`
- `response.audio.delta` events are flowing

### 3. Lipsync is only pre-recorded phrase MP4 matching

Current lipsync path is not full realtime mouth movement.

It only works when:

- `lipsync=1` is in the URL
- PhraseMatcher finds a matching sentence, or
- `lipsync_test=phrase_XXX` is provided

## Recommended Next Step

Build a visible call health panel before deeper avatar work.

Show these states in the UI:

- Auth: signed in / not signed in
- Mic: permission granted / blocked / no device
- Realtime: connecting / connected / failed
- Data channel: open / closed
- Session update: sent / acknowledged
- Audio output: receiving / silent
- Avatar mode: idle / speaking / lipsync

This will make "Sophie is not responding" diagnosable in one glance.

## Longer-Term Architecture Direction

Do not re-enable old multi-MP4 switching as the default.

The correct next visual path is:

1. Keep stable single-video mode as production default.
2. Add a hidden compositor or double-buffer renderer for lipsync/action clips.
3. Only crossfade after the target clip reaches `canplay`.
4. Let `AvatarDirector` stay the only owner of visual state.
5. Enable lipsync behind a flag only after no flicker is verified.

Do not bring back forced `phrase_074` kick into production flow.
